## 0. 先把任务缩小：今天只做三件事

这个项目看起来复杂，是因为它同时包含文献整理、化学判断、数据处理、机器学习和可视化。实际开始时不需要一次做完这些事情。

1. 打开已有地图，看懂一个点对应的反应与来源。

## 1. 这个项目到底想回答什么

### 1.1 用你的实验背景理解项目

你有一个通过改变实际金属体系、并结合定向进化实现非天然反应的蛋白平台。你想知道：已有非酶化学中，哪些转化值得尝试迁移到这个蛋白环境？

人的通常做法是：阅读熟悉的化学，寻找相似活化方式，比较底物、金属、配体和条件，然后决定先尝试什么。

本项目把其中一部分做成可记录、可重复比较的流程：

```text
已知酶反应 + 有出处的非酶先例
              ↓
将反应结构转换成可比较的数字
              ↓
寻找结构相关的转化
              ↓
查看原文条件与迁移障碍
              ↓
形成待核查、待实验的候选清单
```

程序主要帮助组织和筛选证据。它目前不能回答“这个反应放进你的酶里一定能不能发生”。

### 1.2 三种问题不要混在一起

| 问题 | 举例 | 当前项目做到哪一步 |
|---|---|---|
| 结构检索 | 哪些已记录反应与这个转化相似？ | 已实现 |
| 跨催化体系的候选排序 | 哪些非酶反应更值得优先考虑迁移？ | 已有简单评估框架，尚缺核查数据和效果验证 |
| 实际酶催化可行性 | 这个具体蛋白、底物和条件能否产生目标产物？ | 尚不能预测 |

此外，当前程序不是逆合成规划器，也不是蛋白序列设计器。它不会仅凭一个目标产物自动规划完整路线，不会生成突变方案。

### 1.3 为什么化学判断仍然重要

两个反应都形成 C–N 键，并不说明它们有相似的活化方式。例如，酰胺化与卡宾 N–H 插入的化学问题不同。即使净转化相近，反应伙伴能否接近活性位点、竞争路径、介质和金属配位环境也可能不同。

所以我们要分别记录：

- **结构上发生什么**：反应物变成什么产物。
- **在什么体系中发生**：酶、实际金属、配体、光照、介质等。
- **依据是什么**：论文、SI 中的具体实验和机理证据。

目前没有足够信息认定你铜置换体系的全部反应都遵循同一种机理。不能仅从“加铜盐”和“形成 C–O/C–N/C–S/C–C 键”自动推断活性物种。

`cd` 表示进入文件夹；`pwd` 显示当前位置。应看到上面的项目路径。

### 2.2 打开已经生成的地图

最简单的方式：在 Finder 中进入项目目录，双击 `打开反应地图.command`。

或者在终端执行：

也可以直接打开[离线反应地图](../outputs/bioreaction_atlas_v02/reference_demo/map/reaction_map.html)。某些 Markdown 阅读器不允许直接启动本地 HTML，这时用 Finder 或上面的 `open` 命令。

地图已经计算好了。打开文件不会训练模型，不会消耗 GPU 算力券，也不会启动一个服务器。

### 2.3 在地图上实际做什么

1. 找一个蓝绿色点，把鼠标停在上面：浮窗显示反应结构与来源。

6. 点击图例：隐藏或显示一类来源。工具栏支持缩放和重置。

悬停另一个点不会覆盖已经点击固定的详情。点很密时先放大，避免选中重叠的其他点。

## 3. 第一条可以直接运行的反应检索

### 3.1 先确认命令可用

```bash
.venv/bin/bioatlas --help
```

你会看到 `validate`、`encode`、`neighbors`、`map` 等命令。

`.venv` 是这个项目专用的 Python 环境。写完整的 `.venv/bin/bioatlas` 可以直接使用它，不必先执行“激活环境”。`bioatlas` 是程序的命令行入口，不是另一个网站。

### 3.2 用一条已有酶反应查询专利近邻

下例使用当前旧酶库中的一条记录，来源为 `10.1038/s41557-021-00794-z`。它仅作为已有参考查询，尚未在本项目中逐项核查原文，不是我们提出的新反应。

先用计算较轻的 Morgan 基线：

```bash
.venv/bin/bioatlas neighbors data/local/reference_demo/morgan \
  'CNc1ccccc1.[N-]=[N+]=C1CCOC1=O>>CN(c1ccccc1)[C@H]1CCOC1=O' \
  --domain patent_reference \
  --top-k 5 \
  --out outputs/beginner_guide_demo/neighbors_morgan.json
```

应看到：

```text
Returned 5 neighbors
```

命令每一部分的作用：

| 内容 | 意义 |
|---|---|
| `neighbors` | 执行近邻检索 |
| `data/local/reference_demo/morgan` | 使用哪个已经计算好的索引 |
| 单引号内的整段文字 | 查询反应的 SMILES，下一节会解释 |
| `--domain patent_reference` | 只在当前专利参考记录里找 |
| `--top-k 5` | 最多返回前 5 个结果 |
| `--out` 后的路径 | 把结果保存到哪里 |

多行命令末尾的 `\` 表示“下一行仍属于这条命令”。复制时保留它，后面不要加空格。反应字符串外的单引号不能去掉，因为 `>` 在终端里本身有特殊含义。

### 3.3 把结果转换成能看的结构图

```bash
.venv/bin/bioatlas cards outputs/beginner_guide_demo/neighbors_morgan.json \
  --out outputs/beginner_guide_demo/cards_morgan
```

打开查询结构与第一个结果：

```bash
open outputs/beginner_guide_demo/cards_morgan/query.svg
open outputs/beginner_guide_demo/cards_morgan/neighbor_01.svg
```

完整说明在[教学查询的 Morgan 证据卡](../outputs/beginner_guide_demo/cards_morgan/evidence_cards.md)。其中包含相似度、来源、核查状态与条件缺失信息。

看到一个排名靠前的结果后，依次判断：

1. 反应物到产物的变化是否确实相关？
2. 是反应模式相近，还是仅仅都带有某个大骨架？
3. 当前记录是否足以知道实际催化条件？
4. 回到原文后，它是否值得进入人工核查的先例库？

如果结果看起来不合理，也可能是有价值的诊断：参考库没有相关反应，或者这种指纹更关注底物结构。不能为了“让结果好看”直接删去不相关结果而不记录原因。

### 3.4 用 RXNFP 对同一反应再查一次

```bash
.venv/bin/bioatlas neighbors data/local/reference_demo/rxnfp \
  'CNc1ccccc1.[N-]=[N+]=C1CCOC1=O>>CN(c1ccccc1)[C@H]1CCOC1=O' \
  --model-dir data/local/public/rxnfp \
  --domain patent_reference \
  --top-k 5 \
  --out outputs/beginner_guide_demo/neighbors_rxnfp.json

.venv/bin/bioatlas cards outputs/beginner_guide_demo/neighbors_rxnfp.json \
  --out outputs/beginner_guide_demo/cards_rxnfp
```

`--model-dir` 告诉程序去哪里读取已经下载的官方模型。这里是在做模型推理，不是在训练。

对比[RXNFP 证据卡](../outputs/beginner_guide_demo/cards_rxnfp/evidence_cards.md)与 Morgan 的结果。不同方法分数的尺度和意义不同，不能根据“某方法分数更大”就认定方法更好。

本节两个查询和结构卡生成已在当前环境实际运行。重复运行会更新相同路径下的演示输出，不会修改原始参考库。

## 4. 数据为什么分两张表，编号为什么这么多

### 4.1 一篇文章不等于一条反应记录

一篇论文可能包含多个催化体系、多个变体、多个底物，还报告 yield、ee 和 TTN。如果都塞进一个格子，程序无法知道哪个数值属于哪个实验。

当前设计是：

```text
发现事件
  └─ 一个或多个反应体系与条件
       └─ 一个或多个具体实验
            └─ 一个或多个测量指标
```

这是数据的关联关系示意，不是限制一篇论文只能有一个发现事件。

### 4.2 四种编号各管什么

以下编号是教学示意，不代表真实实验：

| 层次 | 示例编号 | 表示什么 | 何时新增 |
|---|---|---|---|
| 发现事件 | `EM_DEMO_D01` | 一项反应能力发现 | 出现另一项独立能力发现 |
| 体系 | `EM_DEMO_C01` | 反应模式、催化体系和条件 | 换金属、配体、光照或关键操作条件 |
| 实验 | `EM_DEMO_A01` | 某底物、变体在该体系中的实验 | 换底物、变体或独立重复 |
| 测量 | `EM_DEMO_A01_YIELD` | 该实验的一个指标 | 同实验再报告 ee、TTN 等 |

同一实验报告 yield 和 ee 时，两行共用 `assay_id`，使用不同 `measurement_id`。不能把它们算成两个独立反应发现。

同一反应能力可能在多篇文章里继续发展。程序不会自动识别这些文章是否属于同一个发现，后续仍需人工统一 `discovery_id`。

### 4.3 第一张表：反应条件

中文工作表名：`反应条件`。英文表名：`Reaction contexts`。内部名字：`contexts`。

一行说明：这是哪个反应体系，它的条件来自哪里。

第一遍必须填的内容：

| 中文字段 | 内部名字 | 如何理解 |
|---|---|---|
| 体系编号 | `context_id` | 唯一且稳定的记录编号 |
| 发现事件编号 | `discovery_id` | 先把同一发现关联起来，后续核对 |
| DOI或公开链接 | `source` | 原论文或永久链接 |
| 条件出处 | `source_locator` | 如 SI 页码、General procedure 编号 |
| 反应名称 | `reaction_name` | 使用作者名称，暂时不追求统一分类 |
| 催化体系类型 | `catalysis_mode` | 酶催化、非酶催化或无催化剂对照 |
| 实际金属及辅因子 | `metal_cofactor` | 记录实验中实际使用的体系 |
| 原文条件摘录 | `conditions_raw` | 可先整体摘录条件，标清单位 |
| 核对状态 | `record_status` | 第一遍可为“待核对” |

酶催化还需要蛋白骨架 `scaffold`；原文确实没说明可写“未报告”。非酶体系可以不填蛋白。固定必填的金属字段若原文未报告，就如实写“未报告”；不要捏造金属。可选数值字段的未知信息则留空。

不用第一遍就把缓冲液、pH、温度、时间全部拆成单独字段。先保留准确的条件原文和位置，后续再结构化。

### 4.4 第二张表：实验结果

中文表名：`实验结果`。英文表名：`Measurements`。内部名字：`experiments`。

一行记录一个实验的一个指标。

至少需要：测量编号、实验编号、体系编号、结果出处、底物至产物编号、实验阶段、检出状态、指标。

有数值时还需要单位和比较符；数值为空时必须保留原文结果。结构可以后补，但具体化合物编号和 SI 位置不能含糊，否则后续无法确认你指的是哪一个反应。

### 4.5 常见记录怎样填写

下表仅演示格式：

| 原文表示 | 数值 | 比较符 | 单位 | 原文结果 |
|---|---:|---|---|---|
| 85% yield | 85 | `=` | `%` | 85% yield |
| <1% yield | 1 | `<` | `%` | <1% yield |
| >99% ee | 99 | `>` | `%` | >99% ee |
| 95:5 dr | 留空 | 留空 | `ratio` | 95:5 |
| n.d. | 留空 | 留空 | 留空 | n.d. |

Excel 的数值列用普通数字 `85` 表示 85%，不要输入 Excel 百分比格式的 `85%`，因为后者内部存成 0.85。程序会检查这个问题。

未检出不等于精确的零产率；未报告不等于失败。如果记录一个未检出的目标产物，产物角色应为“测试目标”，不能填“观察产物”。目标结构必须有文献依据。

### 4.6 三个层次的“通过”不同

| 层次 | 谁判断 | 表示什么 |
|---|---|---|
| 格式校验通过 | 程序 | 编号、字段、单位等符合规则 |
| 人工已核对 | 收集者与复核者 | 结构、条件、来源与原文一致 |
| 可进入严格历史评估 | 程序检查 + 人工证据 | 还需日期、候选定义和发现事件对应关系 |

一份空白模板也可以格式校验通过，只是记录数为 0。程序不会因为你点了“已核对”就真的替你读完 SI。

## 5. 计算机如何读懂一条反应

### 5.1 SMILES 是结构的文本写法

SMILES 可以描述原子及其连接关系。例如：

| 字符串 | 简单含义 |
|---|---|
| `CCO` | 乙醇 |
| `CC=O` | 乙醛 |
| `c1ccccc1` | 苯 |
| `.` | 分开不同分子组分 |
| `@` / `@@` | 与局部原子顺序相关的立体信息，不能直接逐字等同于 R / S |

下面是一个**只用来说明表示方式**的净转化，不是完整配平的实验条件：

```text
CCO>>CC=O
```

完整反应 SMILES 有三个位置：

```text
反应物 > 试剂或agents > 产物
```

中间段可以为空，因而出现 `>>`。但反应物和产物都不能空。只有一个底物的分子 SMILES，不能直接作为当前反应检索的输入。

这里没有矛盾：探索新酶反应时，查询的是已知酶转化或明确提出的目标转化，候选来自已经有反应物与产物记录的非酶先例；当前程序并不是从未知底物自动生成未知产物。

### 5.2 结构标准化实际做了什么

当前 `canonical_reaction()` 会：

1. 把三个段分开，检查两端非空。
2. 用 RDKit 解析每个分子。
3. 去除原子映射编号。
4. 为每个分子生成保留立体信息的规范 SMILES。
5. 在每个段内排序分子组分。

这样，不同书写顺序表示的同一组结构更容易合并。例如 `O.CC` 与 `CC.O` 的组分排序差异不会被当作新化学。RDKit 是解析结构与绘图的化学工具，相关入门见 [RDKit 官方文档](https://www.rdkit.org/docs/GettingStartedInPython.html)。

“规范化”不等于“自动纠正化学”。当前没有自动完成去盐、互变异构归一、反应配平、缺失产物补全或机理判断。

### 5.3 原子映射是什么，为什么现在不要求

原子映射给原子加编号，表示反应前后哪些原子相对应。显式比较断键、成键时，它会很有帮助。

当前四种表示不要求提供这种对应关系，标准化时还会去掉编号。因此现在能做“反应结构相似性”，但没有实现可靠的逐键反应中心匹配，也没有在图上自动高亮断键和成键。

RXNFP 与 RXNMapper 是不同工具；本项目没有因为使用了 RXNFP 就自动获得 RXNMapper 的映射功能。

### 5.4 条件信息到底去了哪里

四种编码器都使用同一种结构视图：

```text
反应物 >> 产物
```

中间 agents 段在生成指纹时被省略。原始反应及条件仍保存在证据记录里。

这意味着：同一结构反应，仅改变中间段的催化剂，当前结构指纹通常不会因此改变。如果催化剂或溶剂被原始来源错误地放在反应物段，程序也不会自动认出它并移走，反而可能影响指纹。

因此，“我们收集了催化条件”与“结构模型已经利用条件”是两件事。第 12 节会解释条件信息的另一条使用路径。

## 6. 指纹、向量和四种表示：它们各自看什么

### 6.1 一串数字为什么可以代表反应

计算机不直接用肉眼比较反应图。它先把反应编码为一个固定长度的数字列表，叫作向量或指纹。

这里的“指纹”只是紧凑表示，并不保证像身份证一样唯一。不同反应可能得到相同或很接近的表示，哈希折叠也可能发生碰撞。

下面是假想数字，**不是实际模型输出**：

```text
反应 A → [0.2, -0.4, 0.8, ...]
反应 B → [0.3, -0.5, 0.7, ...]
```

如果表示学到或编码了适合任务的信息，向量相似就可能对应有意义的化学相似。但这需要通过对照验证，不能只看图上是否聚类漂亮。

### 6.2 四种方法的全貌

| 命令里的名称 | 当前维度 | 看什么 | 当前项目需要训练吗 | 主要用途 |
|---|---:|---|---|---|
| `substrate` | 4,096 | 反应物侧的局部结构 | 不需要 | 判断是否仅靠底物相似就能得到结果 |
| `morgan` | 4,096 | 产物与反应物局部结构计数的差 | 不需要 | 透明、带方向的反应基线 |
| `drfp` | 2,048 | 反应两侧不同的局部子结构集合 | 不需要 | 已发表的非神经网络反应指纹 |
| `rxnfp` | 256 | 官方神经网络对整条反应文本的表示 | 本项目不训练，复用已有权重 | 学习型反应表示对照 |

维度更多不代表方法更好。选择多种方法是为了检验结论是否依赖某一种表示。

### 6.3 底物 Morgan：只看起点

Morgan 指纹围绕每个原子向外观察局部环境，再把这些环境映射到固定位置。

当前底物基线使用半径 2，也就是最多向外看两步键连接；将反应物各组分的局部环境计数相加，得到 4,096 维向量，包含手性设置。

它不使用产物。因此同一组反应物变成不同产物时，这个基线不能区分两种转化。

保留它的科学意义是：如果更复杂的反应指纹并不优于底物基线，那么所谓“学到了反应迁移”可能只是利用了底物长得像。

### 6.4 Morgan 净变化：比较反应前后

当前算法可以概括为：

```text
反应向量 = 所有产物的 Morgan 计数之和 − 所有反应物的 Morgan 计数之和
```

教学示意，假设只有三个特征：

```text
反应物计数 = [2, 1, 0]
产物计数   = [1, 0, 1]
差向量     = [-1, -1, 1]
```

负值表示某些特征计数减少，正值表示增加。但单个位置是折叠后的结构特征，不应直接解释为“一根 C–N 键”。

这是一种有方向的表示。交换反应物和产物，非零差向量会变号。若一个反应的净指纹为零，就无法计算余弦相似度，程序会排除并记录原因。

零指纹不一定意味着“实验没有发生反应”；也可能涉及记录方式或表示损失，需要回到结构检查。

### 6.5 DRFP：保留两侧不共有的结构片段

DRFP 的直观做法是：分别列出反应左右的局部子结构，去掉两侧共同存在的部分，将只在一侧出现的片段编码成二进制指纹。这种集合运算叫“对称差”。该方法由 Probst、Schwaller 和 Reymond 发表。[DRFP 官方实现与论文入口](https://github.com/reymond-group/drfp)

本项目实际调用已安装的 DRFP 包：2,048 维、最大半径 3、包含环片段。它不是 Morgan 计数差的另一个名字。

关键限制：对称差交换左右后不变。所以对于本项目输入的两端结构，标准 DRFP 不区分反应正向和逆向；测试里专门保留了这一性质。它也没有把变化写成带正负号的“形成／消失”。

### 6.6 RXNFP：让神经网络读取反应文本

RXNFP 来自 Schwaller 等人的反应表示工作，发表于 2021 年。它利用基于注意力机制的网络学习反应文本表示。研究包括掩码语言模型预训练及反应分类相关训练；官方提供不同训练版本。[原研究](https://arxiv.org/abs/2012.06051)、[官方指纹生成说明](https://rxn4chemistry.github.io/rxnfp/generate_fingerprints/)

本项目复用官方 `bert_ft` 权重，当前执行过程是：

```text
规范反应 SMILES
    ↓ 化学分词
token 序列
    ↓ 已有 BERT 模型
各 token 的上下文表示
    ↓ 取最后一层开头 [CLS] 位置
一个 256 维反应向量
```

这里的分词不等于逐字符切割，例如方括号中的原子表达需要按规则处理。`[CLS]` 是序列开始处的特殊标记，本项目使用它的最后一层表示作为整条反应的指纹。

本地配置可直接核查：12 层、每层 4 个注意力头、隐藏维度 256、最多 512 个位置。长度检查把特殊标记也算进去；超长或缺少词表 token 的反应会明确排除，不会悄悄截断化学结构。

注意力可以使一个位置结合其他位置的信息。但注意力权重不是催化机理证据，指纹中的某一维也不直接等于“自由基概率”或“能在水中反应的概率”。

当前得到的 256 维向量不是 50 类概率列表，更不是 256 个产物。Schneider50k 的 50 个标签也不是 RXNFP 可接受反应的硬上限。

### 6.7 “训练”和“编码”到底有什么不同

| 操作 | 改变什么 | 当前是否执行 |
|---|---|---|
| 训练／微调 | 根据损失函数更新神经网络权重 | 没有 |
| 编码／推理 | 用固定权重计算输入的向量 | 已执行 |
| 建索引 | 保存反应、证据与向量 | 已执行 |
| 拟合二维投影 | 为这一批向量寻找二维位置 | 已执行 |

`encode` 不会自动微调 RXNFP。增加 100 条文献反应后重新编码，也只是增加或更新索引内容。

t-SNE 自身会优化坐标，但这不意味着训练出了能预测酶可行性的新模型。项目目前也没有对话式 LLM、自动文献代理或蛋白大模型参与运行。

## 7. “相似”究竟怎样算出来

### 7.1 余弦相似度

Morgan、底物 Morgan 和 RXNFP 都用余弦相似度：

```text
cosine(a, b) = a 与 b 的点积 / (a 的长度 × b 的长度)
```

它比较两个向量方向是否接近。理论范围是 -1 到 1；Morgan 差向量含负数，所以负相似度可以出现。

相似度 0.8 不能解释为 80% 的成功率。同一个分数在不同指纹、不同候选库中也不能直接横向比较。

### 7.2 DRFP 的二元 Tanimoto

二进制指纹可以理解为哪些位置被置为 1。Tanimoto 比较共同为 1 的位置占并集的比例：

```text
Tanimoto = 共同出现的位置数量 / 至少在一方出现的位置数量
```

教学示例：A 的位置集合为 `{1, 2, 3}`，B 为 `{2, 3, 4}`，交集有 2 个，并集有 4 个，相似度为 0.5。

### 7.3 一次检索的真实执行顺序

`neighbors` 会：

1. 读取索引及向量文件，检查版本、大小、散列等。
2. 加载与索引参数一致的编码器。
3. 将查询反应编码。
4. 根据 `--domain` 和 `--exclude-source` 筛选可比较的记录。
5. 计算查询与这些记录的相似度。
6. 按分数排序，返回前 k 条，并保留来源证据。

当前实现直接计算与所选候选的相似度，没有实现百万级数据库的近似近邻索引服务。当前几千条参考数据可以直接运行；不能把未来的大规模检索架构当成已经完成。

### 7.4 结果 JSON 中应该先看什么

| 字段 | 含义 |
|---|---|
| `query` | 实际用于比较的查询结构 |
| `eligible` | 过滤后有多少个可比较条目 |
| `hits` | 返回的近邻列表 |
| `similarity` | 这个编码器下的结构相似度 |
| `reaction_smiles` | 对应近邻结构 |
| `evidence` | 支撑该结构点的原始来源记录 |

`top-k=5` 不代表库里有五种可行新反应，只表示最多显示五个排名靠前的结构条目。

当前普通检索也没有默认排除未检出目标。核查过的“测试目标”可以保留在索引中，返回结果时必须看 `outcome` 和 `product_role`，不能把所有命中都当作成功先例。

## 8. 地图怎么产生，为什么不能用它直接判断可行性

### 8.1 从 256 个数字压到两个数字

RXNFP 的一个反应有 256 个数字，屏幕只能用横、纵两个坐标画点。当前地图用 t-SNE 为整批向量计算二维位置。

t-SNE 试图让高维空间中较近的邻居在二维图里仍然较近。它优化的是一种邻域关系的匹配，而不是尽可能原样保留所有距离。[scikit-learn 的 t-SNE 说明](https://scikit-learn.org/stable/modules/generated/sklearn.manifold.TSNE.html)

### 8.2 当前项目使用的具体设置

| 项目 | 当前实现 |
|---|---|
| 默认投影 | t-SNE，可改用 PCA |
| 默认随机种子 | 17 |
| 当前 RXNFP 图输入 | 2,628 个 256 维向量 |
| 默认近邻规模参数 perplexity | 当前数据量下为 30，小样本会自动降低 |
| 优化迭代 | 1,000 |
| RXNFP 投影距离 | 余弦距离 |
| 地图允许的条目数 | 3–10,000 个唯一结构条目 |

这些数值来自本地 `maps.py`，不是对所有 t-SNE 实现的通用要求。

论文原始反应地图工作使用了 TMAP 等工具；当前项目实现的是联合 t-SNE 图，不是原版 TMAP 的完整复刻。

### 8.3 图上的几个常见误读

| 看到的现象 | 可以说什么 | 不能据此说什么 |
|---|---|---|
| 两个点很近 | 值得检查是否有相关结构 | 两种反应能在同一个酶里发生 |
| 蓝色集中在一侧 | 这批来源在此表示下出现分布差异 | 这一侧是天然的“酶可行区” |
| 某片区域没有蓝色点 | 当前所收集酶数据没有覆盖那里 | 从来没有人做过这些酶反应 |
| 某点孤立 | 可能是独特结构，也可能是错误或投影效应 | 它必然是一种重要新反应 |
| 两个簇远离 | 在当前布局中分开了 | 它们的化学差异按屏幕距离线性增长 |

坐标轴不是反应活性、能垒、极性或成功率。添加更多数据并重新拟合时，原来的点也可能移动；当前代码没有固定旧坐标并把新点直接插入的功能。

### 8.4 为什么检索不能看屏幕距离

检索使用原始指纹空间的相似度。二维图有压缩损失，可能改变近邻。

项目还在原始空间计算每个点的 5 个近邻，保存为 `map_data.json` 中的 `knn_edges`；这些边目前不作为可点击的邻居推荐面板显示。

`trustworthiness_at_5` 是投影诊断：检查二维近邻与高维近邻有多一致。即使数值接近 1，也仅说明投影在这个局部指标下失真较小，不是推荐准确率。相应计算仅在代码规定的数据规模下执行。

### 8.5 反应图是怎么画出来的

结构图由 RDKit 从反应 SMILES 生成 SVG。SVG 是矢量图，放大仍可清楚显示键和原子。

当前地图由三部分配合：

1. Plotly 显示散点和缩放交互。
2. 每个点保存自己的记录编号，悬停或点击时据此找到证据。
3. 浏览器读取相邻文件夹中的 SVG，显示反应结构。

图中的箭头和结构并不是 AI 想象出来的。但如果输入 SMILES 有化学错误，RDKit 可能依然画出一个能解析的错误反应，所以绘图成功不等于化学正确。

HTML 内含绘图库，结构图位于 `reaction_structures/`。移动或备份地图时保留整个 `map/` 文件夹；只复制 HTML 会让结构图丢失。

## 9. 目前这些数据从哪里来，覆盖了多少

### 9.1 当前数据的账本

| 来源或处理阶段 | 当前数量 | 怎样理解 |
|---|---:|---|
| 固定 EnzymeEngineeringDB V6 | 1,342 行、36 个非空 DOI | 旧的参考导入，不是全部前沿文献 |
| RXNFP 下的酶结构点 | 640 个 | 合并了相同领域、相同结构的来源行 |
| 已下载 Schneider50k | 50,000 行 | 50 个类别，每类 1,000 行 |
| 真正用于演示的专利样本 | 2,000 行 | seed=17 的独立固定哈希抽样 |
| RXNFP 下的专利结构点 | 1,988 个 | 当前结构标准化后的去重数量 |
| 联合地图 | 2,628 个点 | 640 + 1,988 |
| 用户和同事新收集的前沿数据 | 本次核对时正式录入仍为空 | 不应把旧参考库当作已完成的新数据集 |

专利抽样没有根据与酶反应的相似度挑选。它用固定种子和原始行号的哈希排序抽取，便于复现。

Morgan 和 DRFP 处理这批数据时排除了 18 条零指纹来源行，得到 639 个酶结构点，总数为 2,627。不同编码器的可用样本数可能不同，评估时必须检查共同候选范围。

### 9.2 为什么一千多行只剩几百个点

同一个结构反应可能报告许多突变体或多个指标。新版索引在同一 `domain` 内按标准化结构归并，而把所有来源行放进 `evidence`。

同一个化学结构如果分别出现在酶与专利领域，会保留为不同领域的条目，避免把来源标签混为一谈。

点数不是独立发现数。不同盐形式或组分记录方式也可能导致本应相关的反应没有合并，当前去重不能取代人工判定。

### 9.3 为什么不能直接扩到“所有反应”

50 类专利基准不涵盖所有有机反应，也不只包含催化反应。扩大到完整 50k 可以增加这些类别内的实例，不能自动补齐前沿方法学。

不过，新反应并不需要在这 50 类中才能加入地图。需要的是完整、可解析的反应结构以及证据，然后重新编码。

两三周内更合理的目标是：选定反应家族，结合可访问的 Reaxys／SciFinder 找期刊先例，形成范围清楚、能够检查覆盖缺口的参考池。公开 ORD 可以提供补充背景，但也不等于全文献全集。[ORD 官方说明](https://docs.open-reaction-database.org/en/stable/overview.html)

已有详细方案见[参考库扩充与英文交接说明](../research/reference_library_strategy.md)。

### 9.4 `domain` 标签必须用对

| 标签 | 代表什么 |
|---|---|
| `enzyme_reference` | 当前旧酶库的参考导入 |
| `patent_reference` | 当前专利基准的参考导入 |
| `enzymatic` | 从录入模板转换的酶催化记录 |
| `nonenzymatic` | 从录入模板转换的非酶催化记录 |
| `control` | 无催化剂对照记录 |

`domain` 和核查状态是不同维度。`enzymatic` 也可能是尚未核查的草稿；`patent_reference` 不能直接等同于经过人工证实的非酶成功先例。

在旧参考库上使用 `--domain nonenzymatic` 可能返回 0 条，因为那里面的领域名是 `patent_reference`。这不是所有反应都不相似。

## 10. 从一篇论文开始，怎样真正填出可用数据

### 10.1 先保存自己的工作副本

中文模板位于：

```text
outputs/bioreaction_atlas_v01/非天然酶反应收集模板.xlsx
```

英文模板位于：

```text
outputs/bioreaction_atlas_v02/Nonnatural_Enzyme_Reaction_Collection_EN.xlsx
```

用 Excel 打开中文模板，另存为：

```text
/Users/EasyMaker/Documents/AI4C/data/local/my_collection.xlsx
```

后文使用这个具体文件名，所以另存后就可以直接复制命令。不要把独立示例表里的虚构记录当成真实文献搬进正式表。

不要改表名和表头，不要删除暂时用不到的列，不要合并数据单元格。补充信息写在备注里。程序拒绝导入公式，应粘贴实际值。

### 10.2 第一篇该选什么

优先选你熟悉、原文和 SI 容易获取的一篇文章。第一篇的目的只是验证录入流程，不是代表整个领域。

先找出：

1. 代表性反应及其底物／产物编号。
2. 对应 general procedure 或具体实验条件。
3. 一个明确报告的结果。
4. 蛋白骨架、变体及实际金属。

先填一条体系和一个结果。若同时报告 yield 与 ee，就用两个测量行。随后再补初始活性、进化后结果和关键对照。

结构不会写时，先把 SMILES 留空，结构状态填“待补结构”，把图表位置和化合物编号写清楚。这一步仍然是有效进展。

### 10.3 结构怎么补

如果论文或其公开数据提供反应 SMILES，先检查与图中结构一致，再录入。

若只有结构图，可以用自己熟悉的化学绘图软件重画并导出 SMILES。逐个检查立体中心、形式电荷、保护基、底物与产物对应关系。将分子按反应角色组合为 `reactants>>products`。

当前程序没有自动识别 PDF 结构图的入口，也没有自动连接 Reaxys／SciFinder 导出格式的适配器。不要把一个分子 SDF 文件直接当成已经包含反应物／产物关系的反应文件。

### 10.4 运行格式校验

前提：已经另存了 `data/local/my_collection.xlsx`。

```bash
.venv/bin/bioatlas validate data/local/my_collection.xlsx \
  --out data/local/my_validation.json \
  --normalized data/local/my_curated.json
```

成功时应看到“校验通过”以及体系、测量数量。`warnings` 通常表示日期或结构待补；`errors` 表示必须先修正的问题。

查看报告：

```bash
.venv/bin/python -m json.tool data/local/my_validation.json
```

如果校验失败，本次不会写出新的标准 JSON。若磁盘上留有上一次成功生成的 `my_curated.json`，它不会自动消失，因此必须先确认当前这次校验通过，再执行后面的转换。

### 10.5 什么时候标记“已核对”

当你已逐项确认来源、结构、条件和实验关联时，再把体系核对状态与结构状态设为“已核对”。

你可以先录入草稿而不检索。标准格式允许不完整信息与科研上可信的数据分开管理，不需要为了让程序运行就把草稿全部标成已核对。

### 10.6 外国同事如何加入

让同事使用英文模板和[英文收集指南](Collection_Guide_EN.md)，保存为 `data/local/workmate_collection.xlsx`。程序会将中英文表头和下拉选项转换到同一套内部字段，不需要手动翻译整张表。

当两个文件都已填好、校验无错误时：

```bash
.venv/bin/bioatlas merge \
  data/local/my_collection.xlsx \
  data/local/workmate_collection.xlsx \
  --out data/local/merged.json
```

如果两人独立使用了相同编号，可明确给两个来源加前缀：

```bash
.venv/bin/bioatlas merge \
  data/local/my_collection.xlsx \
  data/local/workmate_collection.xlsx \
  --prefixes EM WK \
  --out data/local/merged.json
```

加前缀会同时更新相关编号和引用。内容不同但编号相同，程序会报冲突而不会替你覆盖；完全相同的同编号行可去重。

注意：加前缀只解决技术编号冲突。同一篇论文被两个人重复收集，或两篇论文对应同一发现，仍需要人工合并科学意义上的重复。

## 11. 把自己的表格变成可检索的库和地图

### 11.1 整条流程只需记住这一行

```text
Excel → validate → 标准JSON → curated-corpus → 语料JSON → encode → 索引 → neighbors / map
```

不同阶段保存不同文件，是为了保留“原始录入”“清洗后记录”“计算结果”之间的区别。

### 11.2 转换为语料

前提：上一节校验成功，已生成 `data/local/my_curated.json`。

```bash
.venv/bin/bioatlas curated-corpus data/local/my_curated.json \
  --out data/local/my_corpus.json
```

如果你使用的是两人合并结果，改为运行这一条输入不同的命令：

```bash
.venv/bin/bioatlas curated-corpus data/local/merged.json \
  --out data/local/my_corpus.json
```

上面两条按你的实际情况选一条。转换会把实验与其对应体系关联起来，并保留测量、发现编号和出处。

### 11.3 先建 Morgan 索引

```bash
.venv/bin/bioatlas encode data/local/my_corpus.json \
  --backend morgan \
  --out data/local/my_morgan
```

默认只接收已核查记录；示例永远排除。至少还需要完整可解析的结构、来源和来源定位；零向量也会排除。

如果输出 `Encoded 0 unique reactions`，先检查核查状态和结构，不要立刻认为模型坏了。

可以查看排除原因与实际条目数：

```bash
.venv/bin/python - <<'PY'
import json
from pathlib import Path
info = json.loads(Path('data/local/my_morgan/index.json').read_text())
print('可检索结构数:', len(info['entries']))
print('被排除的来源行:')
for row in info['excluded']:
    print(row['record_id'], row['reason'])
PY
```

`--allow-unreviewed` 是给明确标为探索的数据使用的选项，可以放行草稿／导入状态，但不会把它们变成已核对；示例、缺少出处和无法处理的结构仍会被排除。初学阶段不要为了消除报错随意加这个参数。

### 11.4 再建立自己的 RXNFP 索引

```bash
.venv/bin/bioatlas encode data/local/my_corpus.json \
  --backend rxnfp \
  --model-dir data/local/public/rxnfp \
  --batch-size 16 \
  --out data/local/my_rxnfp
```

`batch-size` 表示一次送进模型多少条，影响内存和速度，不是训练批次数。当前适配器使用 CPU，即使电脑或算力平台有 GPU，也没有 `--device cuda` 这一接口。

同一语料还可以分别使用 `--backend substrate` 和 `--backend drfp`，输出到不同索引目录。不能把不同编码器的向量混到同一个矩阵里。

### 11.5 生成自己的地图

前提：索引至少有 3 个、至多 10,000 个可用唯一结构条目。

```bash
LOKY_MAX_CPU_COUNT=4 .venv/bin/bioatlas map data/local/my_rxnfp \
  --out outputs/my_collection_map

open outputs/my_collection_map/reaction_map.html
```

`LOKY_MAX_CPU_COUNT=4` 限定部分并行工具看到的 CPU 数量，沿用当前环境设置；不改变模型权重。

这张图只显示 `my_rxnfp` 索引中的记录。**你填表后，旧演示地图不会自动增加这些点。**生成地图会读取指定索引，而不是实时读取 Excel。

如果只有少量条目，地图仅适合检查输入和显示，不应根据几个点的聚类推断化学空间规律。只有 1–2 条时也可以建立索引和检索，只是地图命令不接受。

### 11.6 查自己的反应，一定要把查询写完整

对于上面已经用过的参考查询，可以在自己的库里运行：

```bash
.venv/bin/bioatlas neighbors data/local/my_rxnfp \
  'CNc1ccccc1.[N-]=[N+]=C1CCOC1=O>>CN(c1ccccc1)[C@H]1CCOC1=O' \
  --model-dir data/local/public/rxnfp \
  --domain nonenzymatic \
  --top-k 5 \
  --out outputs/beginner_guide_demo/neighbors_my_library.json
```

这条命令的前提是你的库里已录入非酶反应。没有这类记录时返回 0 条是正常结果。更换查询时只替换单引号内的完整反应 SMILES，保留引号。

你也可以只把自己的反应作为查询，继续搜索已经存在的公开参考索引。这不要求先把查询反应加入那个索引。

### 11.7 想把自己的数据与演示库画在一起

此步骤可选，主要用于探索。不要把混合未核查公开记录的库直接当成严格评估库。

前提：已生成 `data/local/my_corpus.json`，已有演示语料 `data/local/reference_demo/corpus.json`。

```bash
.venv/bin/python - <<'PY'
import json
from pathlib import Path
from bioreaction_atlas.curation import write_json

reference = json.loads(Path('data/local/reference_demo/corpus.json').read_text())
curated = json.loads(Path('data/local/my_corpus.json').read_text())
records = reference['records'] + curated['records']
ids = [row['record_id'] for row in records]
if len(ids) != len(set(ids)):
    raise ValueError('记录编号冲突；请先统一编号，不要覆盖已有记录')
write_json('data/local/combined_exploration.json', {
    'corpus_version': '1.0',
    'purpose': 'combined_exploration_not_historical_benchmark',

    'records': records,
})
print('合并来源行数:', len(records))
PY

.venv/bin/bioatlas encode data/local/combined_exploration.json \
  --backend rxnfp \
  --model-dir data/local/public/rxnfp \
  --allow-unreviewed \
  --out data/local/combined_rxnfp

LOKY_MAX_CPU_COUNT=4 .venv/bin/bioatlas map data/local/combined_rxnfp \

```

这里明确使用 `--allow-unreviewed`，因为演示参考记录都是导入状态。它们的原状态仍保留。新图会重新拟合坐标，不能把位置变化理解为反应性质变了。

### 11.8 Excel 改了以后要重跑哪些步骤

按顺序重跑：校验、语料转换、编码，然后重新检索或画图。

`index.json` 中的散列用于检查所载向量与保存时是否一致，并不会监视 Excel 的变化。**旧索引不会因为表格更新而自动刷新。**不要手工只改 `vectors.npz` 或混用两个目录里的索引文件。

## 12. 催化条件怎么参与：当前只是一个简单基线

### 12.1 当前普通检索没有条件加分

`neighbors` 只算结构相似度。条件虽保存在结果证据中，但不会自动参与它的排序。

条件一致性当前实现于 `evaluate` 的评估流程中。它需要独立整理的标准化标签，不会自动从 Excel 的原文条件里抽取信息。

### 12.2 当前只比较四个条件字段

| 字段 | 指什么 | 为什么还需要人工 |
|---|---|---|
| `metal` | 统一写法的金属标签 | 不应从加盐直接猜活性物种 |
| `activation` | 统一写法的活化方式 | 要区分实验支持与作者提议 |
| `light` | 统一写法的光照标签 | 自由文本不能简单凭词相同判断 |
| `medium` | 统一写法的介质标签 | 需要预先定义比较的粒度 |

每个标签还需要值、来源、具体定位、公开日期、证据类型。当前可接受 `experimental_support` 和 `author_proposal`；项目自己的机理假设不能加入这个历史条件基线。

“作者提出”被允许保存，不等于程序证实了机理。评估时应单独报告证据质量。

### 12.3 分数怎样计算

当前规则：四个字段中，每个双方都有记录且标签相同的字段贡献 0.25；比较时忽略英文大小写，但不自动翻译同义词。

```text
条件一致性 = 相同字段数 / 4
组合分数 = 结构相似度 + 条件权重 × 条件一致性
```

默认条件权重是 0.15，**人为设定、尚未训练和验证**。

教学示例：结构相似度为 0.70；金属与介质一致，活化方式不同，光照缺失。条件一致性为 2/4=0.5，组合分数为 0.775。

这不是 77.5% 成功率。分数甚至可能超过 1，因为它是排序分数而不是概率。

### 12.4 这条规则有什么明显不足

缺失信息不加分，但“不知道”和“已知不一致”都没有获得该字段加分，虽然报告里会分别列出。记录更完整的条目可能因此占优势。

“同一种金属”也不必然意味着容易迁移，配位环境和活性物种可能完全不同；有价值的迁移有时恰恰需要改变条件。当前规则没有建模这些问题。

因此先把它当作需要击败或改进的基线。它没有实现“给定同一底物，切换催化剂后自动改变产物预测”。

## 13. 不做很多湿实验，怎样判断研究有没有用

### 13.1 先做历史回看，但不要偷看答案

基本思路：选一个时间点 T，仅使用 T 之前已知的酶反应和非酶先例，看看程序会把哪些候选排在前面；再检查 T 以后公开的酶反应发现是否被排到前面。

```text
T 之前的酶反应：作为种子
T 之前的非酶反应：构成候选库
T 之后的酶反应发现：用于检查排名
```

这可以测“恢复后来公开发现”的能力，不直接测“未来未报道实验的成功概率”。发表偏倚等问题仍然存在。

### 13.2 一个候选、一条记录、一个发现有什么区别

一个反应候选可以由若干相关非酶结构条目支持。定义候选组时要说明分组规则，不能靠后来的成功标签临时拼出有利的组。

一个发现事件可以与一个或多个候选组有对应关系，也可能根本没有覆盖到的候选。对应关系需要人工化学核查，不能仅凭指纹相近就写成正确答案。

当前候选结构分数取该候选各条目与所有种子之间的最高相似度；组合分数也在同样的条目—种子配对中取最高值。一个候选包含的条目多，会增加得到较高最大值的机会，因此候选组大小也要检查。

### 13.3 三个最重要的数字

以下是假想教学数字，不是项目结果：共 10 个后来的发现，候选库覆盖其中 7 个，前 5 名命中了其中 4 个。

| 指标 | 计算 | 回答的问题 |
|---|---|---|
| 候选覆盖率 | 7/10 = 70% | 库里有没有可以恢复这些发现的候选？ |
| 已覆盖事件 Recall@5 | 4/7 ≈ 57% | 库里已经有答案时，排序找到了多少？ |
| 总体 Recall@5 | 4/10 = 40% | 连同覆盖缺口在内，整体恢复了多少？ |

没有覆盖的 3 个发现不能偷偷删除后只报告 57%。覆盖失败与排序失败是两个不同问题。

### 13.4 与谁比较才有意义

当前框架可以比较：

- 各种指纹的结构分数。
- 结构分数加条件一致性。
- 来源频率：某候选在当前池里出现于多少个不同来源。
- 均匀随机排序的期望命中率。

来源频率不是整个化学文献中的引用热度。不同方法必须面对相同候选池，否则可能只是因为某方法排除了难样本。

分数相同时，评估按并列组内随机排序的期望命中率计算，避免按候选编号字母顺序恰好把正确答案排前。

置信区间通过按论文分组的 bootstrap 估计：每次重采样论文组，保留同一论文内事件的关联。少于两个论文组时不提供这个区间。区间窄也不能弥补事件数量少或数据选择偏差。

### 13.5 当前评估为什么不能直接拿演示数据跑

严格评估要求：

1. 非空种子、固定候选池和后续发现事件。
2. 种子为人工录入的 `enzymatic`，候选为 `nonenzymatic`。
3. 所选条目的所有证据均为已核查，日期早于 T，并有日期依据。
4. 种子有核查过的检出产物证据。
5. 后续发现日期在 T 当天或以后，具有候选对应／缺少覆盖的说明。
6. 条件标签的依据也早于 T。

当前程序还拒绝候选中与种子完全相同的结构转化。这是精确结构检查，不是完整的反应家族新颖性判定。

旧公开参考数据缺少这些人工证据，不能仅改几个标签就变成合格评估数据。

### 13.6 RXNFP 还有预训练时间泄漏问题

即使你整理的候选全在 T 之前，官方预训练模型仍可能见过 T 之后的数据。当前没有建立其训练时间完全符合历史截断的证据。

因此默认严格评估会拒绝 RXNFP；只有明确设置 `allow_pretrained_exploration: true` 才能作为单独标注的预训练探索结果运行。不能把它与无数据训练的基线一起称为完全无泄漏的历史预测。

### 13.7 真正执行评估的步骤

这不是第一天需要做的部分。完整格式见 [EVALUATION.md](EVALUATION.md)。

1. 核查数据并建立各编码器的索引。
2. 从 `index.json` 取得实际存在的条目编号。
3. 将 `templates/evaluation_protocol.json` 另存为 `data/local/frozen_protocol.json`。
4. 填写截断日期、种子、候选组、后续发现、对应依据及可选条件标签。
5. 记录候选池构建规则、冻结时间，以及哪些参数在独立开发数据上选择。
6. 检查四种表示共同支持的条目，再固定比较范围。

只有完成这些人工准备后，才执行：

```bash
.venv/bin/bioatlas evaluate data/local/my_morgan \
  data/local/frozen_protocol.json \
  --k 1 5 10 \
  --condition-weight 0.15 \
  --out outputs/my_evaluation_morgan.json
```

空白协议故意不能运行出结果，不是软件安装失败。协议检查只能检查字段和逻辑，不会自动证明文献检索穷尽、机理正确或事件独立。

## 14. 那么我到底要训练什么

### 14.1 当前版本没有训练任务

程序没有 `train` 命令，也没有训练新候选排序器。现在完成的是：录入、整理、已有表示计算、近邻检索、可视化和评估框架。

收集数据有两个目的：先建立可信的检索与评估依据；如果后续证据足够，再支持方法改进。不是为了凑够数据量而立即训练一个神经网络。

### 14.2 如果以后训练，合理的对象是什么

一种后续方向是小型候选排序模型：输入某个候选与已知酶种子之间的结构、活化方式、介质差异等特征，输出候选的相对优先级。

训练信号需要明确来源，例如开发集里的先例—发现对应关系或有规则的人工相关性判断。没有报道成功的候选不能简单标成失败；发表记录与实验阴性需要区别。

开发集用来决定模型或条件权重，最终测试事件只用于一次独立评估。必须防止同一篇论文的不同底物在训练和测试两边互相泄漏。

**这一段是未来研究选项，当前没有实现。**如果独立事件不足，优先做清楚的覆盖分析与冻结基线，不一定需要训练才能产生可讨论的结果。

### 14.3 为什么现阶段不用算力券

当前瓶颈是高质量结构、条件、来源和独立发现标签，不是 GPU。现有几千条反应的编码已经在 CPU 跑通。

单纯租更贵的 GPU，不会补齐论文条件，不会让没有标签的数据自动变成可监督训练任务。等要解决的训练问题和验证方法明确后，再决定是否使用算力券。

## 15. 两到三周如何安排，才能避免被数据收集拖住

以下是工作计划建议，不是保证产出论文或证明新反应可行。

| 时间 | 主要任务 | 当阶段应得到的东西 |
|---|---|---|
| 第 1 天 | 打开地图、完成示例查询、试填一篇论文 | 知道每个输入和输出是什么 |
| 第 2–4 天 | 确定一个活化／转化家族，收集小批量酶与非酶文献 | 格式校验通过，发现字段缺口 |
| 第 5–7 天 | 核查结构和条件，整理种子与代表性先例 | 第一版可检索、可解释的自有参考库 |
| 第 8–11 天 | 比较指纹，检查覆盖与失败案例 | 初步覆盖表与检索误差分类 |
| 第 12–15 天 | 数据足够则冻结协议并做历史评估；不足则完成探索性分析 | 带边界说明的结果和可复现流程 |
| 第 16–21 天 | 整理证据卡、方法说明、局限与申请展示 | 清楚说明问题、方法、证据和下一步的项目材料 |

先试收集约 5–10 篇相关非酶方法论文，再决定是否扩大。不要同时覆盖所有酶家族和所有 C–X 成键化学。

每一阶段只有一个判断：下一步需要的输入是否真的已经具备。软件跑通与科学结果成立，应分别记录。

## 16. 文件夹和程序模块各自负责什么

### 16.1 作为使用者，先记住五个位置

| 位置 | 保存什么 | 平时怎么用 |
|---|---|---|
| `docs/` | 使用说明与收集指南 | 查步骤和报错 |
| `outputs/` | 地图、结构卡、模板及演示结果 | 打开查看 |
| `data/local/` | 本地原数据、标准 JSON、索引、模型 | 放真实收集和计算数据 |
| `src/bioreaction_atlas/` | 程序源码 | 想理解或修改实现时读 |
| `research/` | 方案、数据审计、实施状态 | 判断科研依据与覆盖边界 |

`data/local/` 的含义是本地工作数据；目录名不等于已有自动备份。请保留论文、SI 和录入表的自己的备份。

### 16.2 一个索引为什么有两个文件

```text
data/local/my_rxnfp/
    index.json      反应条目、来源、排除原因、参数、散列
    vectors.npz     与这些条目逐行对应的数字矩阵
```

`JSON` 是可读的结构化文本；`NPZ` 是压缩保存的数值数组。两者必须配套。256 维表示就是矩阵中一行有 256 个数，行数对应结构条目数。

散列类似文件内容的摘要，用来发现文件与预期不一致。它保证可追踪的文件一致性，不保证数据本身科学正确。

### 16.3 想看代码时按什么顺序读

| 模块 | 最值得先看的内容 | 回答的问题 |
|---|---|---|
| `schema.py` | `CONTEXTS`、`EXPERIMENTS` | 有哪些字段，哪些必填？ |
| `curation.py` | `read_dataset()`、`validate()` | Excel 怎样读入，错误怎样发现？ |
| `localization.py` | 英文标签与选项映射 | 中英文为什么能合并？ |
| `merge.py` | `merge_datasets()` | 编号冲突怎样处理？ |
| `chemistry.py` | `canonical_reaction()`、`fingerprint()` | 结构怎样规范化和做差？ |
| `encoders.py` | `Encoder.prepare()`、`Encoder.encode()` | 四种表示怎样计算？ |
| `corpus.py` | `curated_corpus()`、`encode_corpus()`、`find_neighbors()` | 如何形成语料、索引与排名？ |
| `maps.py` | `render_map()` | 向量怎样投影到二维？ |
| `map_view.py` | `attach_diagrams()`、`write_interactive_map()` | 悬停图与点击详情如何关联？ |
| `cards.py` | `draw_reaction()`、`write_cards()` | 结构和证据卡怎样导出？ |
| `evaluation.py` | `validate_protocol()`、`rank_pool()`、`evaluate()` | 如何避免错误评估，怎样计算指标？ |

不需要从神经网络内部读起。先追踪一条 Excel 记录，直到看到它出现在近邻结果里，更容易理解数据流。

## 17. 常见问题与解决步骤

| 现象 | 常见原因 | 先做什么 |
|---|---|---|
| `.venv/bin/bioatlas` 不存在 | 不在项目根目录，或环境丢失 | 先执行第 2 节的 `cd` 和 `pwd` |
| 提示找不到 `my_collection.xlsx` | 没有按步骤另存工作副本 | 确认 Finder 中的实际名称和扩展名 |
| 模板校验通过但计数 0 | 正式录入表为空 | 示例表不会自动进入正式数据 |
| 校验失败但还能找到旧 JSON | 上次成功输出仍在磁盘 | 当前校验通过后再继续，不使用旧结果冒充新表 |
| 重复编号／找不到体系编号 | 编号冲突或引用拼写不同 | 核查两表关联，协作时使用明确前缀 |
| 不认识的列／缺少表头 | 改过模板列名或删列 | 保留完整表头，补充内容放备注 |
| 拒绝公式或 Excel 百分比 | 单元格不是普通值 | 粘贴数值；85% 按普通数字 85 录入 |
| `Encoded 0` | 草稿、无结构、无出处或零指纹 | 查看索引 `excluded`，不要盲目放宽状态 |
| 反应无法解析 | 不是完整反应 SMILES，或某分子写错 | 检查两个 `>`、两端结构、英文标点 |
| 净变化指纹为零 | 两侧特征抵消 | 回到结构检查；不要自动视为实验失败 |
| `RXNFP token limit exceeded` | 输入超出模型长度 | 核查组分角色，记录编码覆盖损失；不要随意截掉真实结构 |
| RXNFP 缺 token | 词表不支持该结构表达 | 保留原记录，明确排除原因；可比较其他表示的覆盖 |
| 编码器参数与索引不同 | 模型、依赖版本或参数发生变化 | 用匹配环境，或重新构建索引 |
| 查询 0 条 | 领域过滤不匹配或库为空 | 检查 `patent_reference` 与 `nonenzymatic` 的区别 |
| 首个结果就是同篇文献 | 没排除同源记录 | 使用 `--exclude-source`；新版要求与保存的 source 字符串精确一致 |
| 地图无法生成 | 少于 3 条或多于 10,000 条 | 小样本先检索，大库先确定展示子集 |
| 地图有点但结构图不显示 | SVG 文件夹丢失，或仍是旧页面 | 保留整个 map 目录，重新打开／刷新 HTML |
| 修改 Excel 后图没变化 | 旧索引与旧 HTML 尚未重建 | 校验 → 转语料 → 编码 → 画图 |
| 严格评估拒绝旧公开库 | 核查、日期或领域不满足要求 | 完成人工证据整理；不要伪造 checked 状态 |
| 严格评估拒绝 RXNFP | 训练时间线尚未核实 | 按探索性预训练结果单独报告，或用无数据训练基线 |

新版 `--exclude-source` 会排除含该来源的整个结构条目，不是仅隐藏其中一条证据。它并不自动归一 DOI 的所有写法，也没有自动按研究组排除的选项。

### 17.1 只有环境真的缺失时才重新安装

当前 Mac 已有可用环境，不要为了开始使用重复安装。

在新的环境中，本项目已验证的 Python 主版本是 3.11。若系统已安装 Python 3.11，可以在项目根目录执行：

```bash
python3.11 -m venv .venv
.venv/bin/python -m pip install -e '.[test,research,rxnfp]'
.venv/bin/python scripts/fetch_public_assets.py
```

安装依赖和首次下载需要网络；这些重建步骤未在本次文档任务中再次创建新环境验证。实际已验证环境的依赖版本保存在 `requirements.lock.txt`。跨系统恢复时需要核对依赖兼容性，不应假设任意最新版组合都能直接复现。

下载脚本读取固定提交的 RXNFP 权重与 Schneider 文件，并核对大小与 Git blob。文件已存在时会校验，不会直接重新下载。若散列不匹配，不要删除校验逻辑，应先确认文件来源。

它不会下载完整 EnzymeEngineeringDB。完整公开演示的复现还需要指定那份固定 V6 文件，详见项目 [README](../README.md)。打开已有地图与查询已有索引不需要重新找到该 CSV。

## 18. 命令速查：哪些是一套，哪些不能混用

### 18.1 新版主流程

| 命令 | 输入 | 输出 | 使用时机 |
|---|---|---|---|
| `template` | 输出位置、语言 | 空白 CSV 与字段 JSON | 需要重新导出字段，不生成 Excel 工作簿 |
| `validate` | 模板 xlsx、两表 CSV 目录或标准 JSON | 校验报告，可选标准 JSON | 每次填表修改后 |
| `merge` | 多个中英文录入文件 | 合并的标准 JSON | 多人协作 |
| `curated-corpus` | 录入格式数据 | 语料 JSON | 编码前 |
| `import-references` | 固定旧酶 CSV、固定专利 TSV | 未核查参考语料 | 重建公开演示 |
| `encode` | 语料 JSON | `index.json` + `vectors.npz` | 建立某一种表示的索引 |
| `neighbors` | 索引目录、完整查询反应 | 近邻 JSON | 搜索已有反应 |
| `cards` | 新版近邻 JSON | Markdown 证据卡和 SVG | 人工查看结果 |
| `map` | 新版索引目录 | HTML、PNG、结构 SVG、地图 JSON | 看整体分布 |
| `evaluate` | 索引目录、完整评估协议 | 评估 JSON | 科研数据核查完成后 |

所有命令都可以单独查看帮助。例如：

```bash
.venv/bin/bioatlas encode --help
.venv/bin/bioatlas neighbors --help
.venv/bin/bioatlas evaluate --help
```

### 18.2 旧版 `index/query` 是另一套接口

旧版 `index` 生成单个实验级 JSON 索引，`query` 在它上面检索，使用 Morgan 差指纹。新版 `encode/neighbors` 使用结构归并后的目录索引，可比较四种表示。

不要把旧版 `index.json` 直接传给新版 `map`，也不要把旧版 `query` 输出当成新版 `cards` 输入。

`query` 有 `--before` 日期筛选；当前新版 `neighbors` **没有** `--before`。新版严格时间约束在 `evaluate` 协议中检查。阅读其他早期说明时，要留意正在使用哪一套命令。

### 18.3 哪些功能还没有

- 没有自动全文抓取和 PDF 反应图识别。
- 没有 Reaxys／SciFinder 的实时查询连接和通用导出适配器。
- 没有地图页面内输入反应的搜索框。
- 没有直接计算酶催化成功概率的模型。
- 没有从结构相似自动确认机理或反应迁移关系。
- 没有新模型训练流程、蛋白结构建模或突变推荐。
- 没有使用此前讨论的反应描述语言 RDL 或构象描述语言；目前输入仍是 reaction SMILES，也没有分子三维构象编码。
- 没有经过实际科研数据验证的排序提升结论。

这些边界不是要求你先补齐全部功能。它们用于防止把一个已跑通的工程流程误认为已经回答了科学问题。

## 20. 术语与进一步阅读

### 20.1 十个经常出现的词

| 词 | 在本项目中的含义 |
|---|---|
| corpus／语料 | 准备拿来编码的一组结构与证据记录 |
| encoder／编码器 | 把反应结构变成固定长度数字的程序 |
| fingerprint／指纹 | 编码后的数字表示，不保证唯一 |
| embedding／嵌入 | 把对象表示成向量；在这里常指学习得到的反应向量 |
| inference／推理 | 用已训练好的模型计算输出 |
| index／索引 | 保存记录与可供比较的向量，不一定是复杂数据库 |
| nearest neighbors／近邻 | 在所选表示与距离下排名靠前的记录 |
| projection／投影 | 把高维表示放到二维等更低维度 |
| baseline／基线 | 必须比较的简单或既有方法 |
| benchmark／评估基准 | 事先定义输入、候选、答案与指标的测试设置 |
